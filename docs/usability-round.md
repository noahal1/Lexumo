# 这轮改了什么：让它更好用，也更像人做的

审计 + 修改记录。日期 2026-10-27，基线 14 个 commit 的干净工作树。

一句话：**没有换视觉风格**。你的设计系统（暖纸 + 玉绿、纸感层次、衬线标题）本身是好的，问题不在"好不好看"，在**细节在真实使用里露出的破洞**——深色模式有 7 处白字压在白字上、图表在手机上标签被裁成一个数字、Ctrl+1 会在你填了一半的编辑框上把页面切走、提示条盖住手机底部标签栏还会吃掉你的第一次点击。这轮修的就是这些。

## 一、三个最该修的（如果只看三条）

### 1. 深色模式的按钮字是"白底白字"

`src/styles/tokens.css:135` 的深色主题里，`--jade` 被提亮成 `#58cfb2`（浅玉色，为了在深底上能看见），但**按钮上的字还是写死的浅色** `#f7fffc`。

对比度算下来 **1.88:1**。WCAG AA 要求 4.5:1。也就是说深色模式下主按钮的文字几乎看不见——这是这轮最严重的可用性问题，而它出现在每一页的主操作按钮上。

同一个根因在 7 处复制粘贴：`.btn-primary`、`.check.on`（勾选框）、`.tab-badge`（手机标签栏数字）、`.quiz-key`（测验选项的 A/B/C/D）、`.switch-knob`（开关圆点）都是浅色字压在浅玉色上；`.brand-mark` 是 `--jade-ink` 压在 `--jade` 上，**1.38:1**——比 1.88 更糟。另外 `.quiz-key` 和测验的错误选项是白字压 `--rose #e0806e`，**2.81:1**。

修法不是逐个改硬编码，而是**补两个语义令牌**，让"在这个底色上写字该用什么颜色"变成一个可被主题切换的东西：

```css
:root            { --on-brand: #f7fffc; --on-rose: #ffffff; }
:root[data-theme="dark"] { --on-brand: #06231c; --on-rose: #2a0f0a; }
```

深色下改用**深色字**压浅玉底（`#06231c` on `#58cfb2` = **8.68:1**），浅色模式不变。7 个调用点全部改成 `var(--on-brand)` / `var(--on-rose)`。

> 这是这轮唯一一处"改动看起来很大但用户看不出"的地方——它只在深色模式下改变，而深色模式本来就是坏的。

### 2. 手机上的提示条会吃掉你的第一次点击

桌面端提示条浮在右下角没问题。手机上底部有 61px 的标签栏，提示条 `bottom: 24px` 正好压在上面，而提示条容器带 `pointerEvents: auto` ——**你想点"闪卡"标签，点到的是提示条**。

第一次修的时候我写了个 `.app.mobile .toast-stack{...}` 的规则，实测发现**没生效**。原因值得记下来：`ToastProvider` 在 `src/main.tsx` 里是 `.app` 的**兄弟节点**，不是子节点，所以后代选择器永远匹配不上。改成媒体查询（不依赖 DOM 嵌套）才真正修好：

```css
@media (max-width: 720px) {
  .toast-stack { bottom: calc(72px + env(safe-area-inset-bottom, 0px)); }
}
```

实测：`stackBottom: 72, toastTop: 716, tabbarTop: 783` → 不再重叠，且提示条在自己中心点是最顶层元素（可点）。

> 教训：CSS 后代选择器假设了 DOM 关系。这个假设是错的，而且不报错，只是静默失效。

### 3. `scroll-behavior: smooth` 让每次翻页都在滚

`src/styles/global.css:401` 给 `.page` 设了 `scroll-behavior: smooth`，而 `src/App.tsx:115` 在切页时执行 `scrollTop = 0`。

结果：**每换一个页面，你要看着列表慢悠悠滚回顶部**（几百毫秒）。在长词库上尤其难受——你点"闪卡"，看到的是词库列表慢慢往上滑。

删掉那一行。`prefers-reduced-motion` 的保护块（`global.css:1692`）保留，那是给需要减少动效的人的，和这个是两件事。

## 二、按页面说

### 词库（WordsPage / WordEditor）

**批量操作**（新增）：以前要删 20 个词得点 20 次删除、确认 20 次。现在工具栏有「批量选择」——进入后每行出现勾选框，底部浮出一条操作栏：全选 / 收藏 / 删除所选 / 取消。删除仍然要求确认，确认后可以撤销。

删除单个词现在也能**撤销**了：删掉后提示条上出现「撤销」按钮，保留 8 秒，点一下词条连同**它的复习记录**一起回来（`store.restoreWord(word, logs)`）。之前删错了就是永久没了。

**草稿保护**：填了一半的编辑框，点背景或按 Esc 不再直接丢弃，而是问「这个词语还没保存，要丢掉吗？」，两个出口都是明确的：继续编辑 / 丢掉改动。（给 `Modal` 加了 `dismissible` 属性，默认 true 保持老行为，编辑器传 false。）

**回车的行为**：以前在词形输入框按回车会立刻保存并关闭——即使你还没填释义。现在回车是**跳到释义栏**，`Ctrl/Cmd+Enter` 才是从任何位置保存。

**音标**登上桌面：`Word.phonetic` 原来是查到了但没地方存/显示，现在存进词条，行内和闪卡背面都能看到。

**记住你的视图**：列表 / 筛选 / 排序 / 状态选择存进 localStorage（`lexumo.words.view.v1`），下次打开还是你上次的样子，不用每次重设。

**行内按钮的键盘误触**：在行内某个按钮上按回车会**同时**打开编辑器（事件冒泡到行）。加了 `if (e.target !== e.currentTarget) return;`。

### 闪卡（FlashcardsPage）

- **今天复习完了**不再是一句冷冰冰的「这个筛选下没有卡片」加一个禁用的按钮，而是说明今天做完了、给你「去测验」的出口。
- **今日新卡上限**现在有可见解释（`今天的新卡上限是 N 张，剩下的明天再来`），以前上限静默生效，你会以为词库漏词了。
- **新卡的三档评分**其实都落到明天——加了一句说明，而不是三个按钮下面各写一遍「首次 · 1 天」。
- **中途退出**有确认（`还有 N 张没看，退出后这次进度不会保存`），退出后提示「已复习的 N 张都记下了」。
- **听力模式**（`audioFirst`）以前是个死开关——存了值但完全没实现，勾了没有任何反应。现在是真的：正面藏起词形、只显示「先听一遍，再翻面对答案」和发音按钮，翻面才揭晓。

### 测验（QuizPage）

- 答错后**不再 900ms 自动跳下一题**。以前你还没看完正确答案就被推进去了。现在停住等你按「下一题」/ 回车（答对仍可自动推进）。
- 提前结束改为按**已答题目**算正确率，并标注「答了 N / M 题」，不再把一个只答了 3 题的成绩显示成 30 题的百分比。
- 结束确认走 `ConfirmDialog`。

### 统计（StatsPage）

**柱状图的横轴之前是坏的。** 原来每个日列都是一个 `flex: 1 1 0` 的格子，里面装标签，90 天视图下每个标签分到约 10.7px，`overflow: hidden` 把它裁成 `0`、`2` 这样的碎片——你看到的是一排数字，但没有意义。

现在标签是**绝对定位**的：只给 `labelStep` 允许的那几天画刻度，最后一天（今天）**永远**有标签，并固定到右边缘。

这轮实测又发现第二个问题：390px 宽的手机上，30 天视图的最后两个标签**重叠**了——因为按 `i % step` 挑日子的规则没考虑"贴边的标签需要额外空间"。修法是显式处理边界：贴着末尾的刻度会挤到今天的标签，所以**直接丢掉**而不是硬挤。

```ts
const lastIdx = series.length - 1;
const labelIdx: number[] = [];
for (let i = 0; i <= lastIdx; i += labelStep) {
  if (lastIdx - i >= labelStep) labelIdx.push(i);   // 太靠近末尾的刻度不要
}
if (labelIdx[labelIdx.length - 1] !== lastIdx) labelIdx.push(lastIdx);  // 今天一定有
```

实测 18/18：三种宽度 × 三个区间，标签**不裁切、不重叠**，最窄的标签盒 24.1px 装得下 `10/13`。

**柱子的高度需要参照**：加了虚线表示窗口平均值、右上角标出峰值，柱子高度从此有绝对含义。同时修了同一张卡片上两个互相矛盾的「累计」——标题栏是当前窗口的数，页脚是全期总数，现在文案分别说清楚了。

### 设置（SettingsPage）

**「清空所有数据」之前是假的。** `handleWipe` 只调 `wipeAll()` 清本机数据，但**同步会话还在**（token 和 `rev` 存在 localStorage），而且没写墓碑。后果：你点了"无法恢复"的清空，登录状态还在，下次同步会把服务器上的东西**全部拉回来**。文案在骗人。

现在：先 `signOut()` 再清空，登录状态下文案改成诚实的版本（`会先退出登录，再清空这台设备上的所有数据...服务器上的副本还在，重新登录会同步回来`），提示也区分「已退出并清空」和「数据已清空」两种情况。

**同步状态在手机上不可见**：同步状态徽标只在侧栏底部，而手机上侧栏是 `display: none`。现在后台同步失败会弹一次提示（带「去同步设置」按钮），点它跳到设置页并**滚动定位**到同步卡片（`id="set-sync"` + `pendingAnchor`）。

**快捷键说明是三套互相打架的**：设置页「关于」写 `Ctrl N` / `Ctrl F`，但应用实际用的是裸键 `n` 和 `/`。现在快捷键只有一个来源（`src/lib/shortcuts.ts` 的 `SHORTCUTS`），「?」帮助面板和「关于」卡片都从它渲染——显示和实际行为不可能再对不上。

设置页「这次复习里最多先放几张新卡进来。设成 0 就只复习旧词」这类解释也补上了。

### 外壳（App.tsx）

**Ctrl/Cmd+1–5 现在会尊重你正在做的事。** 以前不管你在打字还是在弹窗里，按一下就把页面切走——正在填的词、正在做的测验、正在看的导入预览全部**卸载丢失**。现在这些键只在「没有对话框打开」时生效。

**22 处硬编码中文**进了 i18n：跳转链接、品牌副标题、`aria-label`、侧栏标题、整个快捷键帮助弹窗。切到 English 时外壳不再半中半英。

## 七、技术备注（留给以后的你）

- **`en.ts` 受 `Dictionary` 类型约束**，`zh-CN.ts` 的形状就是它的形状。少一个键 `tsc` 就报错。这是这个项目最好的一个决定——加中文键时英文不跟会立刻被发现。这轮补了 37 个键。
- **37 个键在 HEAD 上就缺失**，不是我改坏的。`translate()` 查不到时返回键名本身，所以它们一直以 `shell.skipToContent` 这样的字面量显示在界面上。是子代理新加的调用点让它们暴露出来。
- **新模块两个**：`src/lib/shortcuts.ts` 是快捷键的唯一来源（作用域 modal > page > app，输入框内单键自动让位）；`src/lib/wire.ts` 是同步线格式的边界，逐字段重建记录，让服务器盖的 `_rev` 无法回写/回推/进备份。
- **`translate.ts` 改动很大**（+326/−158）看着吓人，但它是把适配器注入化（`createLookup`/`LookupCache`/`LookupClock`），符合仓库自己"一个概念一个接缝"的历史风格，不是顺手重构。
- 三个子代理在跑到一半时挂了，留下未使用的导入和半成品功能（`tsc` 报 TS6133）。这些是我接手补完的——批量选择、发音守卫等。**没有留下死代码。**

## 八、追加：动效

后来你说"增加一些动画吧"。这一节是那一轮的记录。

### 原则

这个 app 的底色是纸与玉，安静。所以动效只做两件事：**交代因果**（东西从哪儿来）和**给操作回执**（按下有反应）。不弹跳、不抖动、不循环——`--ease` 家族里没有一个会 overshoot 的曲线。全部可关。

### 加了什么

| 位置 | 动效 | 为什么 |
| --- | --- | --- |
| 翻页 | `.page-inner` 淡入 260ms | 换页时视线有个落点。**只动 opacity**：给页面容器加 transform 会让 sticky 表头失去定位上下文 |
| 词库行 | `row-in` 260ms，每行 +16ms，最多 8 行 | 列表"落下来"。上限是故意的：`animation-fill-mode: both` 在延迟期间是透明的，延迟太长会让筛选后新出现的行迟到 |
| 批量选择栏 | `bar-rise` 260ms | 从原来底部提示的位置升起，读起来是"同一个东西换了内容"，不是凭空多了一条 |
| 仪表盘数字块 | `tile-in` 420ms，+32ms 递增 | 数字依次到位，比一次性全亮好读 |

### 闪卡为什么不用 3D 翻转

两面都绝对定位需要固定高度，会跟现有的 `max-height: 48vh; overflow-y: auto` 打架——长释义要能滚。而且这个环境看不到图，3D 的裁剪和背面穿透问题我验证不了。

所以用两段式：转到侧面（130ms，此时内容不可见）→ 换面 → 转回来（180ms）。`--ease-turn` 让它像纸被翻过来，而不是 UI 元素在滑动。快速连点有守卫（`turn !== "idle"` 直接返回），键盘空格走同一个入口。

### 减少动态

CSS 侧有全局兜底（`animation-duration: .01ms !important`）。但闪卡的换面时序是 JS 排的，CSS 管不到，所以 `src/lib/motion.ts` 的 `prefersReducedMotion()` 在**点击那一刻**读，直接跳过两个定时器，答案立刻出现。

验证时用 CDP 模拟 `prefers-reduced-motion: reduce` 复测：`transform: none`、`is-flipped: true`、时长 `1e-05s`，即真的没有转。

### 怎么验证的

`.shots/verify-motion.mjs` **16/16**，每条都是数值断言，不是"看起来有动画"：computed `animation-name` / `animation-delay`、翻面过程中途采样 `transform` 矩阵、退出时元素仍在 DOM 且动画名是 `toast-out`、之后确实卸载、以及上面那组 reduce 复测。
